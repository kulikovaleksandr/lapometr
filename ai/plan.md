# Лапометр — план разработки

## 1. Видение продукта
«Лапометр» — веб-приложение для учёта ухода за домашним питомцем (кошка, собака и др.)
в игровой форме. Работает с ПК и телефона без установки. Две главные идеи:

1. **Журнал заботы** — каждое выполненное действие (покормил, погладил, поменял лоток)
   фиксируется записью на временной шкале из кружков, соединённых линией.
2. **Соревнование хозяев** — за действия начисляются «лапки» (баллы); два хозяина
   видят, кто заботится лучше, регулярнее и чаще.

## 2. Целевая аудитория
- Владельцы кошек/собак, которые хотят вести историю ухода (прививки, обработки,
  кормления) и не забывать про регулярные процедуры.
- Семьи и пары, ухаживающие за питомцем вместе, — игровая механика мотивирует
  делить обязанности.

## 4. Нефункциональные требования
- Адаптивность: mobile-first, нижняя навигация на телефоне, боковая на десктопе.
- Первая отрисовка < 1 с, всё состояние — синхронно из localStorage.
- Доступность: контрастные темы, фокус-стили, aria-атрибуты на интерактивных элементах.
- Данные не покидают устройство (MVP); архитектура готова к переезду на бэкенд.

## 5. Этапы (см. `tasks.md` и `architecture.md`)
1. **M1. Фундамент** — дизайн-система, темы, иконки, хранилище.
2. **M2. Аккаунты** — регистрация, вход, профиль, гость, демо.
3. **M3. Питомец и активности** — онбординг, CRUD активностей, лимиты.
4. **M4. Журнал и лапки** — таймлайн, очки, уровни, анимации.
5. **M5. Дуэль и хозяева** — приглашения, соревнование.
6. **M6. Напоминания** — расписание «пора», уведомления.
7. **M7. Статистика** — все разрезы, SVG/див-графики.
8. **M8. Полировка** — темы, пустые состояния, export, сборка.

## 6. Критерии готовности (Definition of Done)
- `npm run build` проходит без ошибок; приложение открывается без консольных ошибок.
- Полный пользовательский сценарий проходит без перезагрузки:
  регистрация → питомец → активность → запись в журнале → лапки → приглашение
  второго хозяина (вторая вкладка) → дуэль → статистика.
- Все 5 тем переключаются и сохраняются после перезагрузки.
- Лимиты реально блокируют перевыполнение активности.

## 7. Риски и решения
| Риск | Решение |
|------|---------|
| localStorage ~5 МБ (фото) | Даунскейл аватаров до 256 px (canvas) |
| Мультипользовательность без бэкенда | Общий localStorage-«сервер» + sync между вкладками; миграция на Supabase описана в architecture.md |
| Читерство баллами | Лимиты день/неделя/месяц на каждую активность |
| Забывают отмечать | Напоминания + браузерные уведомления |
