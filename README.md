# 🐾 Лапометр

Журнал заботы о питомце: активности, лапки, напоминания и честная дуэль хозяев.
Работает в браузере с ПК и телефона без установки (и устанавливается как PWA),
данные по умолчанию живут на устройстве, а при желании синхронизируются через Supabase.

> Планирование, архитектура и трекер задач — в папке [`ai/`](ai/tasks.md):
> `plan.md` (требования), `architecture.md` (стек и механизмы), `tasks.md` (45/46 задач закрыто).

## Возможности

- **Журнал-таймлайн** — выполненные активности как кружки на шкале времени: дата, время, вид, хозяин
- **Лапки и уровни заботы** — каждая активность приносит лапки, питомец растёт от «Знакомства» до «Лапы-легенды»
- **12 стандартных активностей** (покормить, вода, лоток, погладить, вычесать, глазки, ушки, когти, прививка, глистогонное…) + свои с настройкой иконки, цвета и цены в лапках
- **Анти-чит лимиты** — ограничение повторов активности в день / неделю / месяц (общие на питомца, enforced и в UI, и триггером в БД)
- **Дуэль хозяев** — второй хозяин подключается по коду; периоды, корона лидера, «гонка 7 дней», вердикты
- **Чат хозяев** — «Перепалка хозяев» прямо в дуэли
- **Напоминания** — интервалы «раз в N часов» по активностям + вет-календарь (прививки, таблетки, осмотры с повторами месяц/год); браузерные уведомления и Telegram-бот
- **Статистика** — 7/30/90 дней, по дням (стек по хозяевам), по активностям, по часам, доли лапок, регулярность по каждому хозяину
- **Несколько питомцев** — свой журнал, активности и дуэль у каждого
- **Фото к записям** — в модалке отметки, миниатюра в таймлайне, лайтбокс
- **5 тем** — Ночь (основная), День, Латте, Лес, Олива
- **PWA** — установка на главный экран, офлайн-режим, шорткаты «Журнал / Дуэль / Статистика»

## Стек

| Слой | Технология |
|------|-----------|

## Быстрый старт (локально)

### Требования

- **Node.js 20+** (проверить: `node -v`)
- npm 10+ (идёт в комплекте с Node)

### Установка и запуск

```bash
# 1. Клонируйте репозиторий и перейдите в папку
git clone <адрес-репозитория> lapometr
cd lapometr

# 2. Установите зависимости
npm install

# 3. Запустите dev-сервер
npm run dev
# → http://localhost:5173
```

Готово. База данных на этом шаге **не нужна** — приложение работает в local-first
режиме: аккаунты, питомцы, журнал и лапки хранятся в localStorage браузера.

### Продакшен-сборка

```bash
npm run build     # соберёт dist/
npm run preview   # локальный сервер для проверки собранной версии
```

`dist/` — чистая статика (SPA): раздаётся любым хостингом (Vercel, Netlify,
Cloudflare Pages, nginx, GitHub Pages с rewrite на `index.html`).

### Демо-доступ

| Режим | Как войти |
|-------|-----------|
| **Демо** | Кнопка «Демо-режим» на экране входа: кот **Булка** (2 хозяина, 30 дней истории) + попугай **Кеша**. Логин `demo@lapometr.app` / пароль `demo123` |
| **Гость** | Кнопка «Продолжить как гость» — чистый аккаунт с онбордингом |
| **Свой аккаунт** | Регистрация по e-mail и паролю (пароль хэшируется, хранится локально) |

> Сессия хранится в `sessionStorage` — **в каждой вкладке свой логин**.
> Чтобы поиграть в дуэль: откройте вторую вкладку → войдите вторым аккаунтом →
> введите код приглашения (Настройки → Хозяева). Журнал синхронизируется мгновенно.

## База данных: три режима

```
┌─ Без БД (по умолчанию) ─ localStorage, работает сразу
├─ Supabase Cloud ──────── hosted-проект на supabase.com (бесплатный план)
└─ Self-hosted Supabase ── те же сервисы в Docker-контейнерах на вашей машине/сервере
```

Подключение облака делается **без перекомпиляции**: Настройки → «Облако и
синхронизация» → вставить Project URL и anon key → войти (e-mail или Google).

### Режим 1. Без БД (local-first)

Работает из коробки. Ключи браузера:

| Ключ | Что хранит |
|------|-----------|
| `lapometr.db.v1` (localStorage) | вся база: пользователи, питомцы, активности, записи, чат, вет-события |
| `lapometr.session.v1` (sessionStorage) | логин вкладки |
| `lapometr.activepet.v1` (sessionStorage) | выбранный питомец вкладки |
| `lapometr.theme.v1` | тема оформления |
| `lapometr.telegram.v1` | настройки Telegram-бота |

Ограничение: данные на одном устройстве / в одном браузере (второй хозяин — соседняя вкладка).

### Режим 2. Supabase Cloud (рекомендуется для прода)

1. Зарегистрируйтесь на [supabase.com](https://supabase.com) и создайте проект (Free plan).
2. Откройте **SQL Editor** и по очереди выполните две миграции из этого репозитория:
   - [`supabase/migrations/001_init.sql`](supabase/migrations/001_init.sql) — таблицы, RLS-политики,
     анти-чит триггер лимитов, функция `claim_invite()`;
   - [`supabase/migrations/002_chat_photos.sql`](supabase/migrations/002_chat_photos.sql) — чат хозяев и фото к записям.
3. Включите провайдеры входа: **Authentication → Providers → Email** (включён по умолчанию)
   и **Google** (см. раздел «Google OAuth» ниже).
4. Скопируйте **Settings → API**: `Project URL` и ключ `anon public`.
5. В приложении: Настройки → «Облако и синхронизация» → вставить URL и ключ →
   «Проверить и подключить» → войти или зарегистрироваться.
6. «Отправить в облако» / «Загрузить из облака» — снапшот-синхронизация
   (с подтверждением перед заменой локальных данных).

Что это даёт: настоящий вход с любого устройства, e-mail/Google-аккаунты,
RLS-защита «хозяин видит только своего питомца», лимиты, которые не обойти даже из DevTools.

### Режим 3. Self-hosted Supabase в Docker

Полноценный Supabase (Postgres, GoTrue-auth, PostgREST, Studio) в контейнерах —
для локальной разработки и приватного хостинга.

```bash
# 1. Клонируйте официальный репозиторий Supabase
git clone --depth 1 https://github.com/supabase/supabase
cd supabase/docker

# 2. Подготовьте окружение
cp .env.example .env
# Отредактируйте .env: смените POSTGRES_PASSWORD,
# сгенерируйте JWT_SECRET / ANON_KEY / SERVICE_ROLE_KEY (например, openssl rand -hex 32)

# 3. Поднимите стек
docker compose up -d
```

| Сервис | Адрес |
|--------|-------|
| API (Kong) | `http://127.0.0.1:8000` ← это ваш **Project URL** |
| Studio | `http://localhost:3000` (логин `supabase` / `this_password_is_insecure_and_should_be_updated`) |
| Inbucket (письма auth) | `http://localhost:54324` — сюда приходят ссылки подтверждения e-mail |

Дальше:

```bash
# 4. Накатите миграции Лапометра (вариант А — через psql)
psql "postgresql://postgres:<POSTGRES_PASSWORD>@127.0.0.1:5432/postgres" \
  -f ../../lapometr/supabase/migrations/001_init.sql
psql "postgresql://postgres:<POSTGRES_PASSWORD>@127.0.0.1:5432/postgres" \
  -f ../../lapometr/supabase/migrations/002_chat_photos.sql
# вариант Б — открыть Studio → SQL Editor → вставить файлы и Run
```

```bash
# 5. Возьмите anon-ключ
grep ANON_KEY .env
```

В приложении подключите: URL `http://127.0.0.1:8000`, ключ — `ANON_KEY` из `.env`.
Письма с подтверждением регистрации ловите в Inbucket (`localhost:54324`).

> Для прода self-hosted: поднимите тот же compose-стек за nginx/Traefik с HTTPS
> (GoTrue требует `https` для cookie на внешнем домене) и прокиньте
> `SUPABASE_PUBLIC_URL=https://app.ваш-домен`.

### Сравнение режимов

| | Без БД | Supabase Cloud | Self-hosted Supabase |
|---|---|---|---|
| Старт | сразу | ~10 минут | ~20 минут + Docker |
| Мультиустройство | ✗ (вкладки) | ✓ | ✓ |
| Google OAuth | ✗ | ✓ | ✓ |
| Данные | ваш браузер | облако Supabase | ваш сервер |
| Стоимость | 0 | Free plan | ваш хостинг |
| RLS / анти-чит в БД | — | ✓ | ✓ |

## Google OAuth

1. [console.cloud.google.com](https://console.cloud.google.com) → создайте проект →
   **APIs & Services → OAuth consent screen** (External, добавьте себя в тестировщики).
2. **Credentials → Create OAuth client ID** (Web application):
   - Authorized redirect URI:
     - Cloud: `https://<REF>.supabase.co/auth/v1/callback`
     - Self-hosted: `http://127.0.0.1:8000/auth/v1/callback`
3. В Supabase: **Authentication → Providers → Google** → вставьте Client ID и Secret → Save.
4. В Лапометре появится рабочая кнопка «Продолжить с Google».

## Telegram-напоминания

1. Создайте бота у [@BotFather](https://t.me/BotFather) → получите **токен**.
2. Узнайте свой **Chat ID** у [@userinfobot](https://t.me/userinfobot) (или напишите боту в группу и возьмите id из getUpdates).
3. В Лапометре: Настройки → «Напоминания в Telegram» → токен, chat id →
   «Проверить и отправить тест». Чекбоксы: активности и/или вет-события.

Раз в 30 секунд приложение собирает все «пора» (просроченные активности + события
вет-календаря на сегодня) в одно сводное сообщение; каждое напоминание уходит
один раз (дедупликация). Токен хранится только в браузере.

## Установка как приложение (PWA)

- **Desktop (Chrome/Edge):** кнопка «Установить» в шапке приложения, либо иконка
  установки в адресной строке.
- **Android:** Chrome → меню → «Установить приложение».
- **iOS:** Safari → «Поделиться» → «На экран „Домой"».

После установки Лапометр работает офлайн (service worker кэширует оболочку,
шрифты и ассеты; данные local-first по определению).

## Безопасность — что важно знать

- Локальный режим: пароли хэшируются (djb2), но сама база доступна в DevTools —
  это режим «для себя», не для публичных данных.
- Облачный режим: доступ ограничен RLS-политиками на уровне Postgres; лимиты
  активностей проверяются триггером `enforce_log_limits()` — накрутка
  невозможна даже прямым запросом к API.
- Никогда не коммитьте `service_role`-ключ Supabase и `.env` self-hosted стека;
  в приложении используется только публичный `anon`-ключ.
